# ZONEFALL — Unreal Engine 5.6 Port Architecture

This document maps the browser implementation onto **Unreal Engine 5.6** so a PC-based team can rebuild ZONEFALL at full AAA fidelity. It is a port *architecture*, not a port plan: every system below lists the browser source that exists today and the UE 5.6 target (class, component, module, or subsystem). The browser build is the design contract — identical data tables (`shared/src/weapons.ts`, `zone.ts`, `vehicles.ts`) and identical rules (`damage.ts`, `ballistics.ts`) carry over 1:1 into UE Data Assets / GAS.

**Port mapping legend:** `Browser: src → UE: Target`

---

## 1. World & Terrain

| Browser | UE 5.6 target |
|---|---|
| `shared/src/worldgen.ts` terrainHeight/fbm/ridge | `Landscape` (8 km, 4 tiles, 508×508 quads) + `LandscapeMaterial` with Material Layers; height generated by the same noise function via a Python/HLSL re-implementation of `fbm`/`ridge` for parity |
| `regions.ts` region metadata | `DataAsset` (`UZonefallRegionData`) — center, radius, tints, densities; used by world partition per-region loading |
| Biome tint / vertex colors | Runtime Virtual Texture (RVT) blends: grass, sand, rock, snow, city concrete — auto-blend by height/slope/region weight |
| `render/terrain.ts` vertex-color mesh | `Landscape` layers + `Nanite` is NOT for Landscape; use `Virtual Heightfield Mesh` where needed |

**World Partition:** regions map to `UWorldPartition` cells (256 m). Streaming: `AWorldSettings` runtime hash, `HLOD` per region; hidden bunkers load with their parent region cell.

**Sea/rivers:** `render/water.ts` → `Water` plugin (`UWaterBodyRiver`/`Ocean`) + `WaterBodyLake`; river splines follow Ember River path; `BuoyancyComponent` on boats (maps `vehicle-sim.ts` watercraft flag).

## 2. Rendering & Visuals

| Requirement | UE 5.6 solution |
|---|---|
| Nanite | All static building geometry (`buildings.ts` kits) built as Nanite meshes; windows emissive as separate translucent pass |
| Lumen | `r.Lumen.DiffuseIndirect` on; sky light + directional sun; emissive windows feed Lumen GI |
| Virtual Shadow Maps | `r.Shadow.Virtual.Enable=1`; 8 km shadow cascade via VSM per region |
| HDR / post | `Bloom`, `AutoExposure`, `ToneMapper` (ACES); HDR emissives on all lights |
| Volumetric clouds | `VolumetricCloud` component + `SkyAtmosphere` (day cycle drives sun direction/sky color) |
| Day/night | `SunSky` blueprint lerp — replicate `render/sky.ts` cycle timing |
| Wind | `Niagara` wind module + `WindDirectionalSource` driving foliage (`HierarchicalInstancedStaticMesh` vertex wind) |
| Vegetation | `HISM`/`Foliage` tool: 2 tree kits + grass (`grass_` HISM with wind); densities from `vegDensityAt` |
| Particles | Niagara: muzzle flash, tracers (`NiagaraBeam`), explosions, parachute, smoke (GPU) |
| Mobile profile | `Scalability` levels: Mobile = Lumen off → baked `VolumetricLightmap`, VSM off → CSM single cascade, Nanite on for distant foliage via `Nanite Landscape`? — mobile: static baked lighting + `Mobile Forward`, 60 fps via `r.Mobile.ShadingPath`, dynamic res `r.DynamicRes.Enable` |

## 3. Gameplay Framework Mapping

| Browser | UE 5.6 |
|---|---|
| `world.ts` entity store | `AGameModeBase` + `UZonefallGameInstance` + `AZonefallPlayerState`; actors: `AZonefallCharacter`, `AZonefallItem`, `AZonefallVehicle`, `ABullet` |
| `player-controller.ts` movement | `UCharacterMovementComponent` custom: `CustomMovementMode` for Skydive/Parachute; `AZonefallCharacter` exposes yaw/pitch |
| `combat.ts` ballistics | Projectile `AActor` (projectile movement `UProjectileMovementComponent` with custom gravity via `bUseAddedGravity`/custom tick), hit → `UDamageType` + `TakeDamage`; penetration via `LineTraceMulti` on `ECollisionResponse` material query + `UPhysicalMaterial` `PenetrationResistance` |
| `weapons.ts` | `UDataAsset` `UWeaponData` (same fields: dmg/rpm/mag/recoil/spread/muzzle/gravity/pen/adsMult) + `UZonefallWeaponComponent` (fire modes) |
| `items.ts` / armor | GAS: `UZonefallAttributeSet` (Health, Armor, Stim, Suppression) + `UGameplayEffect` Blueprints; heals = `InstantExecution` effects; vests = `DurationEffect` attribute |
| `damage.ts` formulas | `UZonefallAttributeSet::PostGameplayEffectExecute` — identical formulas incl. limb multipliers from hit bone names (head/chest/abdomen/arm/leg via physics assets) |
| `zone.ts` | `AZonefallZoneActor` — replicate `ZoneState` struct (center/radius/next) to all clients; shrink = `FTimerManager` per stage; `UCustomDamage` outside circle |
| `loot.ts` | `UZonefallLootTable` DataAssets; `ALootSpawnVolume` (Box + `Foliage`-like spawner) seeded by match seed |
| `vehicle-sim.ts` | `AWheeledVehicle` (Chaos) + `UChaosWheeledVehicleMovementComponent` with tuned maxSpeed/accel/turn; tire damage via `SetTirePressure`, engine via `SetEngineTorque`; fuel = GameplayAttribute |
| `ai-nav.ts` | `ANavigationData`/`NavMesh` generated from Landscape (same waypoint graph idea; `UNavigationPath`), bots = `AController` + `BehaviorTree` (drop/loot/rotate/engage/heal/drive as BT tasks + services) + `UAIPerceptionComponent` (sight) |
| `bot.ts` tiers | `UDataAsset UBotTierData` (vision/aimError/reaction); `BTTask_Engage` reads tier |
| `match.ts` lifecycle | `AGameMode::StartMatch/AbortMatch` — Lobby (`AActor` plane `AZonefallPlane`), Flight (`AircraftPath` spline + `UProjectileMovement`-like), Playing, Ended; `RestartPlayer` |
| `sync.ts` (delta snapshots) | Replication: `UNetDriver` replication with `NetUpdateFrequency` 30; dirty tracking = `ReplicatedUsing`; `bOnlyRelevantToOwner` for per-client culling (replaces distance-cull); `FRepMovement` quantization matches `qf()` precision |
| `net.ts` | `UZonefallBeaconClient`/`Server` + `UKismetSystemLibrary` sessions; auth via EOS `UOnlineSubsystemEOS` |
| `validation.ts` | Server-side validation in `ServerFire/ServerMove` RPCs: `ValidateInput` clamp identical to browser (rpm gate, speed caps) |

## 4. Networking / Dedicated Servers (UE 5.6)

- **Listen vs dedicated:** dedicated `-server` builds; `UDedicatedServer` package. 100 players → `MaxPlayers=100`; per-tick budget guard.
- **Architecture:** authoritative `AServerPlayerController` receives `ServerMove` RPCs (input buffer), runs `UCharacterMovementComponent` simulation, replicates back. Client prediction: `UCharacterMovementComponent::ReplicateMoveToServer` — same design as browser `predict.ts`; lag compensation: `UServerMove` saved moves + `Sweep` history rewind (`UNetDriver::ClientAdjustment`).
- **EOS integration** (`ONL_EOS`): `EOSAuth` (Epic account or anonymous), `EOSMCPM` matchmaking (100-player lobbies), `EOSStats` leaderboards, `EOSAchievements`, `EOSSessions` friends/clans. Cloud save via `UE.CloudSave` (EOS Player Data Storage).
- **Voice:** `UOnlineSubsystem` voice (EOS `EOS_PlayerDataStorage` + VIVOX/EOS Voice plugin).
- **Anti-cheat:** EOS Anti-Cheat (`UE_ANTICHEAT`) server + client side; server-authoritative damage/zone/loot as in browser (no client trust); rate limiting on RPCs.
- **Reconnect:** session persistence via EOS `P2P`/`Sessions` + `PlayerState` restore (server keeps dead/alive state 60 s).
- **Replay:** `UReplaySubsystem` + `INetworkReplayStreaming` (EOS replays) — mirrors `replay.ts` event log.

## 5. Audio

| Browser | UE |
|---|---|
| `audio.ts` WebAudio procedural | MetaSounds (`UMetaSoundSource`): procedural gunshots (noise+filter), footsteps (impulse+filter), zone tone, plane rumble; Wwise optional for mix |
| Suppression/heartbeat | `UDynamicSoundMix` with suppression attribute input |
| Occlusion | `USoundAttenuation` occlusion by line trace |

## 6. UI

Browser `ui/*` DOM → UE: `UMG` widgets: HUD (bars, ammo, compass), minimap (`UMaterial` render target for minimap, `UCanvasPanel` overlay), inventory (`UWidgetComponent` or full-screen `UUserWidget`), kill feed, settings, end screen; accessibility: `Slate` accessibility + colorblind materials (lerp by `UZonefallUserSettings` colorblind mode), `Widget Scaling` for UI scale. Gamepad support via `UEnhancedInputComponent`.

## 7. Backend / Live Service (see LIVE-SERVICE.md)

Browser backend (roadmap: Node APIs) → UE live-service: `UE.Online` (`UOnlineSubsystem`), EOS for auth/saves/stats; custom REST APIs for seasons, battle pass, missions, analytics (as in `TECHNICAL-DESIGN.md` backend spec).

## 8. Build Pipeline

- PC: `BuildCookRun` (Win64, DX12/Vulkan); Android: `BuildCookRun -platform=Android -target=Android_ASTC -TextureFormat=ASTC`; iOS: `-platform=IOS -RenderingSystem=Mobile`.
- CI: UE `RunUAT` on GitHub Actions (`ue-build` images); asset manifests per region for chunked `Pak` streaming.
- Perf report template in `DEPLOYMENT.md`.

## 9. Port Order (recommended)

1. **Terrain+World Partition** (Landscape + RVT, regions) — visual milestone
2. **Character movement** (custom modes: walk/skydive/parachute) + dedicated server loop
3. **Weapons/GAS** (data assets, fire modes, ballistics, damage) — port shared tables first
4. **Zone + match lifecycle** (replicated)
5. **Loot/inventory** (spawn volumes + UI)
6. **Bots** (NavMesh + BT + tiers)
7. **Vehicles** (Chaos wheels + fuel + damage)
8. **Live service + anti-cheat** (EOS), **audio** (MetaSounds), **UI** (UMG), **polish** (Niagara, Lumen pass, VSM)

## 10. Parity Checklist

- [ ] Weapon stats table identical to `shared/src/weapons.ts` (exported JSON)
- [ ] Damage formulas identical to `damage.ts` (limb mults, armor ratio 0.6, falloff curve)
- [ ] Zone stages identical to `zone.ts` (6 phases, reachable-circle constraint)
- [ ] Vehicle tuning identical to `vehicles.ts`
- [ ] Input semantics identical (f/s axes, lean, ADS, sprint)
- [ ] Perf targets: 60/120/240 fps tiers honored by scalability settings
